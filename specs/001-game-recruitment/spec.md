# Feature Specification: ゲーム募集掲示板 初版

**Feature Branch**: `3-specify作成`

**Created**: 2026-09-26

**Status**: Draft

**Input**: User description: 「その場で一緒に遊ぶ仲間を募集できる掲示板。会話で確定した登録、募集、即時参加、キャンセル、締め切り、合流情報、マイページの要件を仕様化する。」

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 遊びたいゲームの募集を探す (Priority: P1)

訪問者は登録せずに受付中の募集を探し、ゲームや予定、参加者を確認できる。

**Why this priority**: 仲間を見つけるという掲示板の入口となる。

**Independent Test**: 状態と開始日時が異なる募集を用意し、未ログインで一覧・詳細を確認する。

**Acceptance Scenarios**:

1. **Given** 複数の受付中の募集がある、**When** 一覧を開く、**Then** 開始予定日時が近い順に表示される。
2. **Given** 3種類のゲームの募集がある、**When** ゲームを選ぶ、**Then** 選んだゲームの受付中の募集だけが表示される。
3. **Given** 満員・手動締め切り・中止・開始済みの募集がある、**When** 一覧を開く、**Then** それらは表示されない。
4. **Given** 未ログインの訪問者、**When** 募集詳細を開く、**Then** 公開情報と募集者・参加者の表示名、参加人数／募集人数を確認でき、合流情報とログインIDは見られない。
5. **Given** 条件に合う募集がない、**When** 一覧を開く、**Then** 該当する募集がないと分かる。

### User Story 2 - 登録して仲間を募集する (Priority: P1)

利用者はアカウントを登録してログインし、自分が遊ぶゲームの募集を公開できる。

**Why this priority**: 探す対象となる募集を利用者自身が作成できる必要がある。

**Independent Test**: 新規登録からログイン、募集作成、ログアウトまで実行して公開内容を確認する。

**Acceptance Scenarios**:

1. **Given** 未使用のログインIDと有効な登録情報、**When** 登録する、**Then** アカウントが作成され、そのIDとパスワードでログインできる。
2. **Given** 既存のID、**When** 英字の大小だけを変えたIDで登録する、**Then** 重複として拒否される。
3. **Given** 登録済みの利用者、**When** 誤ったIDまたはパスワードでログインする、**Then** ログインできず、認証情報が一致しない旨が表示される。
4. **Given** ログイン済みの利用者、**When** 必須項目を満たして募集を作成する、**Then** 参加人数0人の募集が公開され、自分の作成募集に表示される。
5. **Given** 入力制限に違反した登録・募集内容、**When** 送信する、**Then** 作成されず、修正が必要な項目と理由を確認できる。
6. **Given** ログイン済み、**When** ログアウトする、**Then** 募集作成・参加・マイページの利用には再ログインが必要になる。
7. **Given** 公開済みの募集、**When** 募集者がタイトル・ゲーム・募集文・開始日時・募集人数を変更しようとする、**Then** 変更できない。

### User Story 3 - 募集に参加して合流情報を確認する (Priority: P1)

利用者は受付中の募集に即時参加し、合流情報を確認して一緒に遊ぶ準備ができる。

**Why this priority**: 応募・承認を挟まず仲間が集まることが本機能の中心である。

**Independent Test**: 受付中の募集と募集者以外のアカウントを用意し、参加から合流情報の閲覧まで確認する。

**Acceptance Scenarios**:

1. **Given** ログイン済みで未参加の利用者と空きのある募集、**When** 参加する、**Then** 承認なしに参加が確定し、人数とマイページに反映される。
2. **Given** 参加中で開始前かつ中止前、**When** 合流情報を開く、**Then** 登録内容、または「合流情報は未登録」が表示される。
3. **Given** 自分の募集または参加済みの募集、**When** 参加を試みる、**Then** 新たな参加は作成されない。
4. **Given** 未ログイン、または募集が受付中でない、**When** 参加を試みる、**Then** 参加できず人数も変わらない。
5. **Given** 残り1枠の募集、**When** 異なる2人が同時に参加する、**Then** 1人だけ参加が確定し、もう1人には参加できなかったことが分かる。
6. **Given** 参加により定員に達した募集、**When** 状態を確認する、**Then** 満員となり新たな参加を受け付けない。

### User Story 4 - 参加をキャンセルする (Priority: P2)

参加者は予定が変わった場合、開始前に自分の参加を取り消せる。

**Why this priority**: 空いた枠を他の利用者に戻し、実際の参加予定を正しく伝える。

**Independent Test**: 参加済みの募集を用意し、キャンセル後の人数、一覧、マイページ、合流情報の権限を確認する。

**Acceptance Scenarios**:

1. **Given** 開始前の参加者、**When** キャンセルする、**Then** 人数が減り、自分の参加募集から消え、合流情報を閲覧できなくなる。
2. **Given** 満員で開始前かつ手動締め切り・中止なし、**When** キャンセルで空きが出る、**Then** 自動で受付中に戻り一覧に表示される。
3. **Given** 手動締め切りまたは中止された開始前の募集、**When** 参加者がキャンセルする、**Then** 人数は減るが募集は再開しない。
4. **Given** 開始予定日時以降、または他人の参加、**When** キャンセルを試みる、**Then** 変更できない。
5. **Given** キャンセル後の利用者、**When** 再び受付中の同じ募集に参加する、**Then** 再参加でき、マイページにも戻る。

### User Story 5 - 募集を管理する (Priority: P2)

募集者は募集を手動で締め切り、必要に応じて再開・中止し、合流情報を更新できる。

**Why this priority**: 募集者の都合に合わせて受付と開催を管理できる。

**Independent Test**: 自分の募集と別ユーザーの募集を用意し、状態と期限に応じた操作の可否を確認する。

**Acceptance Scenarios**:

1. **Given** 開始前かつ中止前の募集、**When** 募集者が手動で締め切る、**Then** 新たな参加を受け付けなくなる。満員時でも手動締め切りとして扱い、空きが出ても自動再開しない。
2. **Given** 手動締め切りで開始前かつ空きがある、**When** 募集者が再開する、**Then** 再び受付中となる。
3. **Given** 開始前かつ中止前、**When** 募集者が中止する、**Then** 開催中止と表示され、参加・再開・合流情報の編集と参加者による閲覧ができなくなる。
4. **Given** 開始前かつ中止前、**When** 募集者が合流情報を登録・更新する、**Then** 参加者が次に確認した際に更新内容を閲覧できる。満員・手動締め切り中も編集できる。
5. **Given** 開始予定日時以降、**When** 参加・キャンセル・締め切り・再開・中止・合流情報の編集を試みる、**Then** 操作できない。
6. **Given** 別ユーザーの募集、**When** 管理操作を試みる、**Then** 変更できない。
7. **Given** 開始済みまたは中止の募集、**When** 合流情報を確認する、**Then** 募集者本人だけが閲覧できる。

### User Story 6 - 自分の募集と参加予定を確認する (Priority: P2)

利用者はマイページから自分の募集と参加している募集を確認し、必要な操作に進める。

**Why this priority**: 一覧に表示されなくなった募集も確認・管理できる。

**Independent Test**: 複数の状態の作成募集と参加募集を用意して、自分の分だけ表示されることを確認する。

**Acceptance Scenarios**:

1. **Given** 作成・参加した募集がある、**When** マイページを開く、**Then** 作成募集と参加募集を分けて確認でき、満員・手動締め切り・中止も表示される。
2. **Given** 開始日時を過ぎた募集、**When** マイページを開く、**Then** 過去の募集として確認できる。
3. **Given** 参加をキャンセル済み、**When** マイページを開く、**Then** その募集は参加募集に表示されない。
4. **Given** 自分の募集・参加がない、**When** マイページを開く、**Then** 各一覧が空であると分かる。
5. **Given** 募集作成・参加・締め切り・中止の操作が成功している、**When** 再読み込みまたはログアウト後に再ログインする、**Then** 操作結果が保持されている。

### User Story 7 - テスト用データを初期化する (Priority: P3)

検証担当者はテスト環境のアカウントと関連データを削除・初期化し、検証を繰り返せる。

**Why this priority**: 利用者向け退会機能を追加せず、再現可能な検証を行える。

**Independent Test**: テスト用アカウント・募集・参加を用意し、初期化後に同じIDで登録からやり直す。

**Acceptance Scenarios**:

1. **Given** テスト環境に検証用のアカウント・募集・参加がある、**When** 検証担当者が初期化する、**Then** 対象データが消え、参照先のない募集・参加が残らず、同じIDで再登録できる。
2. **Given** 通常の利用者、**When** アプリを利用する、**Then** テスト用の削除・初期化機能は利用できない。

### Edge Cases

- 開始予定日時ちょうどから参加・キャンセル・管理操作・参加者の合流情報閲覧を拒否する。直前は他の条件を満たせば許可する。
- 古い画面を開いたまま操作しても、操作時点の人数・状態・時刻・権限で可否を判断する。
- 同時参加や同一人物の連続操作でも、定員超過・重複参加・人数の二重減算を起こさない。
- キャンセルと手動締め切りが重なっても、手動締め切り後に意図せず自動再開しない。
- 中止済みの募集は、開始日時を過ぎても中止と分かる表示を保つ。
- 募集人数は1と9を受け付け、0・10・小数・未入力を拒否する。
- 各文字数の最小・最大・その範囲外を検証する。必須テキストは空文字・空白のみを拒否する。
- 一覧にないゲーム、実在しない日時、現在以前の開始日時では募集を作成しない。
- ログインIDの大小だけが異なる同時登録でも、作成されるアカウントは1つだけとする。
- 未参加・キャンセル済み・未ログインの人は、詳細の場所を知っていても合流情報を閲覧できない。
- 閲覧制限は以後の提供を止めるもので、利用者が既に読んだ情報や保存したコピーを消す機能ではない。
- 存在しない募集には、募集が見つからないと表示する。

## Requirements *(mandatory)*

### Functional Requirements

以下の要件はすべて必須とする。

- **FR-001**: ログインID・パスワード・表示名による登録、ログイン、ログアウトを提供する。
- **FR-002**: ログインIDは非公開、半角英数字とアンダースコアの3〜30文字とし、英字の大小を区別せず一意とする。ログイン時も大小を区別しない。
- **FR-003**: 表示名は日本語を含む1〜30文字、空白のみ不可、重複可とし、募集者・参加者の識別表示に使う。パスワードは15〜128文字とし、大文字・小文字を区別する。詳細な補完方針はAssumptionsに記載する。
- **FR-004**: 募集の一覧と公開詳細は誰でも閲覧できる。募集作成・参加・個人向けの操作とマイページはログインした本人に限る。
- **FR-005**: ゲームはVALORANT、Apex Legends、Overwatchの固定一覧から選択させる。
- **FR-006**: 募集の入力項目と制限は以下の表に従い、不正な入力では作成・更新せず、修正できる説明を表示する。

| 項目 | 必須 | 制限 |
| --- | --- | --- |
| ゲーム | はい | 固定一覧のいずれか |
| 募集タイトル | はい | 1〜100文字、空白のみ不可 |
| 募集文 | はい | 1〜2,000文字、空白のみ不可 |
| 開始予定日時 | はい | 作成が成立する時点より未来の実在する日時 |
| 募集人数 | はい | 募集者を除く整数1〜9人 |
| 合流情報 | いいえ | 最大1,000文字 |

- **FR-007**: 日時は日本時間で入力・表示する。公開直後の参加人数は0人とする。
- **FR-008**: 公開後は合流情報だけ編集可能とする。他の項目の変更、募集の削除は提供しない。
- **FR-009**: 一覧は受付中の募集のみを開始予定日時の昇順に表示し、ゲームで絞り込める。
- **FR-010**: 公開詳細にはゲーム・タイトル・募集文・開始日時・募集者と参加者の表示名・参加人数／募集人数・募集状態を表示する。
- **FR-011**: 募集者以外のログイン利用者は、受付中の募集に即時参加できる。応募・承認は行わない。
- **FR-012**: 同一利用者の重複参加と定員超過を、同時操作を含めて防ぐ。募集者は人数に含めない。
- **FR-013**: 参加者本人は開始前にキャンセルできる。満員・手動締め切り・中止後も開始前なら可能とし、人数と参加者一覧に反映する。
- **FR-014**: キャンセル後は参加募集一覧から除外し、合流情報の閲覧を許可しない。受付中なら再参加できる。
- **FR-015**: 募集状態は下記の状態ルールに従い、開始時刻・定員・手動操作を反映する。
- **FR-016**: 募集者本人は開始前かつ中止前に手動で締め切れる。満員中も手動締め切りを設定できる。
- **FR-017**: 手動締め切りの募集は、募集者本人が開始前かつ空きありの場合に再開できる。
- **FR-018**: 募集者本人は開始前に中止できる。中止は取り消せず、参加者にも中止を表示する。
- **FR-019**: 合流情報の登録・更新は募集者本人に限り、開始前かつ中止前に許可する。未入力に戻すこともできる。
- **FR-020**: 合流情報の閲覧は下記の権限表に従う。閲覧可能な人に対して、未入力の場合は「合流情報は未登録」と表示する。
- **FR-021**: マイページには自分の作成募集と参加募集を分けて表示する。満員・手動締め切り・中止・開始済みも残し、開始後は過去の募集として確認できる。
- **FR-022**: すべての操作で現在の状態・時刻・本人の権限を確認し、許可されない操作では状態を変えず理由を表示する。
- **FR-023**: アカウント情報、募集、参加、締め切り・中止の結果は、再読み込みや再ログイン後も保持する。
- **FR-024**: テスト環境で検証担当者がアカウントと関連する募集・参加を削除・初期化できる手段を用意する。通常の利用者には提供しない。

#### 募集の状態ルール

上から優先して状態を判定する。「開始前」は現在時刻が開始予定日時より前であることを示す。

| 状態 | 条件 | 新規参加 |
| --- | --- | --- |
| 中止 | 募集者が中止した | 不可 |
| 開始済み | 中止でなく、開始予定日時以降 | 不可 |
| 手動締め切り | 開始前で手動締め切り中 | 不可 |
| 満員 | 開始前、手動締め切りなし、参加人数が定員に到達 | 不可 |
| 受付中 | 開始前、中止・手動締め切りなし、定員に空きあり | 可 |

満員からキャンセルで空きが出れば受付中に戻る。手動締め切りと中止はキャンセルでは解除しない。
開始済み・中止は受付中に戻さない。再開は手動締め切りのみを解除する。

#### 合流情報の閲覧・編集権限

| 利用者と募集の状態 | 閲覧 | 編集 |
| --- | --- | --- |
| 募集者本人、開始前かつ中止前 | 可 | 可 |
| 募集者本人、開始済みまたは中止 | 可 | 不可 |
| 参加中、開始前かつ中止前 | 可 | 不可 |
| 参加中、開始済みまたは中止 | 不可 | 不可 |
| 未参加・キャンセル済み・未ログイン | 不可 | 不可 |

#### 初版の対象外

- ログインID・表示名・パスワードの変更、忘れた場合の復旧、利用者向け退会。
- メールアドレスの登録・確認、メール通知。
- ゲームの追加・編集画面、管理者向け画面。
- チャット、コメント、通知機能、通報、ブロック。
- 公開後の募集本文等の編集、募集削除、応募・承認。

### Key Entities *(include if feature involves data)*

- **アカウント**: 一意な非公開ログインID、本人確認に用いるパスワード、公開表示名を持つ。募集を作成し、他人の募集に参加する。
- **ゲーム**: 固定の3タイトル。各募集は1つのゲームを対象とする。
- **募集**: 募集者、ゲーム、タイトル、募集文、開始予定日時、募集人数、非公開の合流情報、手動締め切り・中止の状態を持つ。人数と時刻を含めて受付可否を決める。
- **参加**: アカウントと募集の関係。参加中の人数・表示名・合流情報の閲覧資格・マイページ表示の根拠となる。キャンセル後は参加中として扱わない。

## Success Criteria *(mandatory)*

### Measurable Outcomes

以下は初版の受け入れ目標であり、達成済みの結果ではない。

- **SC-001**: 用意した募集に対し、未ログインの利用者がゲームで絞り込み、希望する募集詳細を1分以内に開ける。
- **SC-002**: 有効な登録情報と募集文を用意した利用者が、登録・ログイン・募集公開を5分以内に完了できる。
- **SC-003**: ログイン済みの利用者が募集詳細から参加し、合流情報を30秒以内に確認できる。
- **SC-004**: 残り1枠に10人が同時参加する検証で、成功は1人だけとなり、定員超過・重複参加が0件である。
- **SC-005**: 状態ルールと合流情報の権限表の全ケース、および開始日時の直前・ちょうど・直後の検証で、期待する可否と表示が100%一致する。
- **SC-006**: 初めて利用する5人中4人以上が説明者の補助なしに、募集検索・参加・キャンセルを完了し、受付中・手動締め切り・中止の違いを正しく説明できる。
- **SC-007**: テストデータの初期化後、同じログインIDで登録から募集・参加までの検証を2回連続でやり直せる。

## Assumptions

以下は会話で個別指定されなかった細部を補う初版の前提であり、変更する場合は実装より先に本仕様を更新する。

- パスワードは15〜128文字とし、空白のみは不可。空白や日本語を含め使用でき、文字種の組み合わせを強制しない。入力を自動で短縮・前後削除しない。
- 文字数はUnicodeのコードポイント数で数え、改行も1文字として扱う。ログインID以外の文章はプレーンテキストとして扱い、入力内容が命令として動作しない。
- 任意の合流情報の空文字・空白のみは未登録として扱う。
- 日時入力は分単位とし、指定した分の00秒を開始時刻とする。未来の日時に追加の上限は設けない。
- 一覧は1ページ20件とし、次のページで続きが見られる。同じ開始日時なら作成の古い順にし、同時作成でも並びを固定する。
- マイページは開始前と過去に分け、開始前は開始日時の近い順、過去は新しい順とする。中止も開始日時に応じた区分に残す。
- 一覧から消えた募集でも、詳細の場所を知っている人は公開部分を閲覧できる。合流情報の制限は常に適用する。
- 自動更新・通知は要求しない。再表示や操作時には最新の状態を反映し、過去に開いた画面からの操作でも制限を回避できない。
- 同じ時刻帯の複数募集への参加、複数募集の作成を制限しない。募集者による参加者の除外機能は設けない。
- 中止は参加履歴を消さない。参加者が開始前にキャンセルした場合のみ、その人の参加募集一覧から消える。
- テスト用初期化はテスト環境全体のアカウント・募集・参加を空にする手段で要件を満たす。固定ゲーム一覧は残す。個別削除画面や通常運用のデータ削除機能は要求しない。
- 初版では募集・参加履歴の自動削除期限は設けない。キャンセル履歴を利用者に提供する必要はない。
- ゲーム本体や外部チャットとの連携には依存しない。募集者が入力した合流情報を参加者自身が利用する。
- 成功基準の時間と人数は初版の検証目標として補完したもので、実装技術や大規模運用の性能を指定するものではない。
