# Feature Specification: アカウント 初版

**Feature Branch**: `3-specify作成`

**Created**: 2026-10-03

**Status**: Draft

**Input**: User description: 「アカウント関連と掲示板関連の仕様を分けて管理する。既存の登録・ログイン・ログアウト要件を移管する。」

**Related Feature**: [掲示板仕様](../001-game-recruitment/spec.md)。本仕様は登録・認証・アカウント情報を管理し、募集ごとの操作権限は掲示板仕様が管理する。

## User Scenarios & Testing *(mandatory)*

### User Story 1 - アカウントを登録する (Priority: P1)

利用者はログインID・パスワード・表示名を登録して、自分のアカウントを持てる。

**Why this priority**: 自分の募集・参加を識別する前提となる。

**Independent Test**: 掲示板機能なしで登録を行い、登録した情報でログインできることを確認する。

**Acceptance Scenarios**:

1. **Given** 未使用のIDと有効な登録情報、**When** 登録する、**Then** アカウントが作成され、そのIDとパスワードでログインできる。
2. **Given** 既存のID、**When** 同じIDまたは英字の大小だけ異なるIDで登録する、**Then** 重複として拒否される。
3. **Given** 必須項目の不足・不正な形式・文字数範囲外、**When** 登録する、**Then** 作成されず、修正が必要な項目と理由が表示される。
4. **Given** 他人と同じ表示名で未使用のID、**When** 登録する、**Then** 別のアカウントとして登録できる。

### User Story 2 - ログイン・ログアウトする (Priority: P1)

利用者は登録した情報でログインし、利用終了時にログアウトできる。

**Why this priority**: 操作する本人を識別し、ログインが必要な機能を利用できるようにする。

**Independent Test**: 登録済みアカウントでログイン・ログアウトし、本人として扱われる状態を確認する。

**Acceptance Scenarios**:

1. **Given** 登録済み、**When** 正しいIDとパスワードを入力する、**Then** その利用者としてログインできる。IDの英字の大小は区別しない。
2. **Given** 誤ったIDまたはパスワード、**When** ログインする、**Then** ログインできず、認証情報が一致しない旨が表示される。
3. **Given** ログイン済み、**When** ログアウトする、**Then** ログインが必要な操作は再ログインまでできない。
4. **Given** 登録後にログアウトした利用者、**When** 再びログインする、**Then** 同じアカウントとして認識され、表示名が維持される。

5. **Given** ログインから1時間経過した、**When** ログインが必要な操作をする、**Then** 再ログインを求め、操作による変更は行わない。期限直前まで操作していても延長しない。
6. **Given** 同じアカウントでPCとスマホにログイン中、**When** PCでログアウトする、**Then** PCのログインは使えなくなり、スマホは自身の期限まで利用できる。
7. **Given** 同じブラウザの複数タブでログイン中、**When** 1つのタブでログアウトする、**Then** 同じログイン状態を共有する他のタブでも、以後の認証が必要な操作はできない。

### Edge Cases

- 同じIDまたは大小だけ異なるIDで同時に登録しても、アカウントは1つしか作成しない。
- IDは2・3・30・31文字、表示名は0・1・30・31文字、パスワードは14・15・128・129文字で境界を確認する。
- 表示名とパスワードは空白だけの入力を拒否する。
- パスワードの大小・前後の空白は区別し、入力を自動で変更しない。
- ログアウト後の古い画面から操作しても、ログイン済みとして扱わない。
- 表示名が同じ利用者でも、別の本人として識別する。
- 有効期限の直前は利用可能、ちょうど1時間後からは利用不可とし、再ログインで新たな有効期間を開始する。
- ログアウト完了後は、以前のログイン情報を再利用しても操作できない。

## Requirements *(mandatory)*

### Functional Requirements

以下はすべて必須とする。ACC-FRはアカウント仕様の要件IDである。

- **ACC-FR-001**: ログインID・パスワード・表示名による登録を提供する。
- **ACC-FR-002**: ログインIDは非公開、半角英数字とアンダースコアの3〜30文字とし、英字の大小を区別せず一意とする。ログイン時も大小を区別しない。
- **ACC-FR-003**: 表示名は公開、日本語を含む1〜30文字、空白のみ不可、重複可とする。
- **ACC-FR-004**: パスワードは15〜128文字、空白のみ不可、大文字・小文字を区別する。パスワードを他の利用者へ公開しない。
- **ACC-FR-005**: 登録したIDとパスワードでログインできる。不一致の場合はログインさせず、認証情報が一致しない旨を表示する。
- **ACC-FR-006**: ログアウトできる。ログアウト完了後は、そのブラウザのログインを使った操作を許可しない。他のブラウザ・端末のログインは維持する。
- **ACC-FR-007**: 無効な入力では登録せず、入力の修正に必要な説明を表示する。同時登録時もIDの一意性を守る。
- **ACC-FR-008**: 登録情報は再読み込み・ログアウト後も保持し、再ログイン時は同じアカウントとして識別する。
- **ACC-FR-009**: 他の機能がログイン中の本人と公開表示名を識別できるようにする。重複可能な表示名を本人判定の根拠にしない。募集者・参加者としての権限は掲示板仕様に従う。

- **ACC-FR-010**: ログインの有効期間は成功時点から1時間とする。操作による延長と自動更新は行わず、期限以降は再ログインを必要とする。
- **ACC-FR-011**: 同じアカウントの複数ブラウザ・端末での同時ログインを許可し、有効期限とログアウトをログインごとに扱う。同じブラウザでログイン状態を共有するタブは一緒にログアウトする。

#### 初版の対象外

- ログインID・表示名・パスワードの変更。
- ID・パスワードを忘れた場合の復旧、利用者向け退会。
- メールアドレスの登録・確認、メール通知。
- 管理者向けアカウント管理画面。
- ログインの自動延長・更新、全端末の一括ログアウト。
- 募集・参加・マイページの募集一覧は掲示板仕様の範囲とする。

### Key Entities *(include if feature involves data)*

- **アカウント**: 一意の本人として識別され、非公開ログインID、認証に使うパスワード、公開表示名を持つ。
- **ログイン状態**: 現在操作している利用者が、どのアカウントの本人として確認されているかを表す。ログアウトまたはログインから1時間の経過により終了する。

## Success Criteria *(mandatory)*

### Measurable Outcomes

以下は受け入れ目標であり、達成済みの結果ではない。

- **ACC-SC-001**: 有効な入力を用意した利用者が、登録からログインまで2分以内に完了できる。
- **ACC-SC-002**: 10人が同一ID（大小違いを含む）で同時登録する検証で成功は1件となる。
- **ACC-SC-003**: 正しい認証情報・誤った認証情報・ログアウト後の操作と入力境界の全検証で、期待する結果が100%一致する。
- **ACC-SC-004**: 初めて利用する5人中4人以上が補助なしに登録・ログイン・ログアウトを完了できる。

## Assumptions

- パスワード条件は分割前の仕様の補完方針を引き継ぐ。空白や日本語を使用でき、文字種の組み合わせを強制しない。自動で短縮・前後削除しない。
- 文字数はUnicodeのコードポイント数で数え、改行も1文字として扱う。表示名はプレーンテキストで扱い、命令として動作させない。
- 登録後の自動ログインは要件に含めず、登録後に明示的にログインする手順で満たせる。
- テスト用アカウントと関連データの初期化は、[掲示板仕様](../001-game-recruitment/spec.md)のFR-024とUser Story 7を共通の結合検証要件として参照する。利用者向け退会は提供しない。
- 登録から募集公開まで5分以内という結合目標は掲示板仕様SC-002で管理する。
- ACC-SC-001とACC-SC-004はアカウント機能を独立して検証するための補完目標であり、結合目標の代替ではない。
